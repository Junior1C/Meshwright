## Быстрый старт

1. Поставьте **Python 3.10 или новее** с [python.org](https://www.python.org/downloads/windows/) — в установщике включите **«Add python.exe to PATH»**. Проверена версия Python 3.12.
2. Скачайте Meshwright и **распакуйте ZIP в обычную папку**, например `C:\Meshwright` (запуск изнутри ZIP ставит всё в папку, которую Windows потом удалит).
3. Запустите `install.bat`, затем `start.bat`.

```bash
git clone https://github.com/GeekatplayStudio/Meshwright.git
cd Meshwright
install.bat          # или:  .\install.ps1
start.bat            # или:  .\start.ps1
```

Модели под рукой нет? На пустом экране нажмите **«Загрузить демо-модель»** — мелкий битый тестовый объект соберётся в памяти, ничего не скачивается и на диск не пишется.

<div align="center">
<img src="docs/images/01-empty.png" width="860" alt="Meshwright при первом запуске">
</div>

Язык интерфейса переключается кнопкой **EN/РУ** в верхней панели, выбор запоминается.

### Что делает установщик

Он собирает изолированный `.venv` рядом с программой — на машине ничего не меняется. Обязательные пакеты ставятся готовыми колёсами — компилятор не нужен. Тяжёлые движки ставятся **по одному**, сбой одного не роняет всю установку. Чего не хватило — показывается, а метод, которому этого не хватает, так и скажет при выборе, а не упадёт молча: `.venv\Scripts\python scripts\check_install.py` покажет, что именно есть в вашей копии.

### 2 · Ремонт — шесть стадий, каждая измерена

```
Чистка → Ориентация → Закрытие дыр → MeshFix → MeshLab → Manifold3D → Воксельный ремеш
```

Стадия записывается в исправления, только если диагностика реально изменилась. Конвейер крутится, пока сетка не перестанет меняться, затем **перепроверяет результат с нуля** — отчёт, который вы видите, намерян на починенной сетке, а не предсказан.

### 3 · Текстуры и PBR — доезжают до конца

Meshwright сохраняет текстуры, с которыми пришла модель, и не даёт им сползти, что бы вы с ней ни делали.

**Он их находит.** Текстуры, запечённые в файл (GLB, glTF, FBX), читаются из материала модели — включая FBX, где картинка вшита внутрь и рядом с моделью искать нечего. Текстуры, на которые файл только ссылается — OBJ с `.mtl` или папка PNG рядом, — находятся по имени, включая раскладки Meshy, Tripo, Sketchfab и Blender: `model.png`, `*_baseColor`, `*_Normal_OpenGL`, `*_Roughness`, `*_AO`, а пакеты `*_ORM` / `*_metallicRoughness` разбираются по каналам. Некоторые генераторы вшивают в FBX пустышку 2×2, а настоящие карты на 2048 кладут рядом отдельными файлами; Meshwright пустышку игнорирует и берёт настоящие файлы.

**Они не сползают.** Текстурные координаты лежат по углам граней, рядом с сеткой, а не внутри неё, — геометрия остаётся честно сваренным телом, пока они едут вместе с ней. Ремонт и децимация текстурированной модели не разваливают её на кучу островов, а оценка готовности считается по настоящей геометрии. Замеренный дрейф после упрощения до 1/50 числа граней: меньше полтекселя на карте 2048.

<div align="center">
<img src="docs/images/14-reduced-wireframe.png" width="900" alt="Текстурированная модель, ужатая с 2,96 млн до 40 000 граней">
<br><em>2 964 400 → 40 000 треугольников, на 98,7% меньше, максимальное отклонение поверхности 0,025 мм — а PBR-материал всё ещё лежит правильно.</em>
</div>

**Проверьте под свой принтер.** Выберите машину на панели — их встроено 216, смола и филамент: Elegoo, Anycubic, Phrozen, Creality, Bambu Lab, Prusa и ещё два десятка марок — и Meshwright измерит, осилит ли машина мелочь в модели физически. Смоляной принтер упирается в экран (у Elegoo Mars 4 Ultra 153,4 мм на 8520 пикселей — пиксель 18 мкм); филаментный — в сопло. Одна и та же модель на одном будет идеальна, на другом — безнадёжна. Слишком тонкое перечисляется и подсвечивается на модели по клику, а где мелочь потеряется — говорится размер, при котором уцелеет всё. Он **сообщает и показывает, модель не трогает** — печатать крупнее, на другой машине, утолщать или смириться с потерей: решать вам. Ничего не утверждается, пока не сошлись два независимых замера: что подтвердить нельзя — помечается, потому что проверка, которая молча гадает, хуже никакой.

**Развернуть, сгенерировать, покрасить, запечь.** **Развернуть UV** строит раскладку, не трогая геометрию, — герметичная модель остаётся герметичной, оценка не двигается. **Загрузить картинку / Сгенерировать PBR** выводит карты нормалей, шероховатости, металличности, затенения и высоты из любого фото или текстуры. **Экспорт карт** пишет все каналы плюс прозрачную UV-подложку — слоем в Photoshop или GIMP; **Перезагрузить карты** забирает правки обратно; **Сохранить запечённый GLB** пишет один самодостаточный файл. Всё, что пишет Meshwright, — с залитыми швами-канавками, чтобы на стыках островов не было тёмных каёмок.

### 5 · Упрощение — умная ретопология до лоу-поли

Три движка, одна абсолютная цель по граням, пресеты от **500** до **50k**:

- **Умная ретопология** — [QuadriFlow](https://github.com/hjwdzh/QuadriFlow), quad-ремешер из Blender. Перестраивает поверхность чистыми ровными quad-ами по форме. Лучше для скульпта, сканов и настоящего лоу-поли.
- **Децимация** — схлопывание рёбер по quadric-метрике. Самая резкая; держит жёсткие края.
- **Равномерная** — изотропный ремеш равными треугольниками, затем схлопывание. Лучше для шумных сканов.

Каждое упрощение сообщает, насколько результат ушёл от оригинала, в миллиметрах и в процентах от размера. Без гаданий.

> Ремешеры умеют открывать дыры на топологически сложных формах. Meshwright проверяет каждый остров результата и чинит его через MeshFix — или переходит на другой движок, — так что упрощение никогда не отдаёт сетку хуже, чем дали. Сам QuadriFlow крутится в дочернем процессе с бюджетом две минуты на остров: это нативный код, который умеет падать и висеть непредсказуемо, и ни то ни другое не должно забирать вашу сессию.

### 6 · Острова

Клик по несвязанному острову во вьюпорте выбирает его. **Shift+клик** добавляет/убирает острова из выбора; клик по пустому месту снимает выбор. Выбранные краснеют и синхронны со списком. **«Удалить выбранные»** — удаляет. Перетаскивание по-прежнему крутит модель.

Модели из нескольких частей разбираются, красятся и перечисляются с числом треугольников и размерами. Отметьте ненужные — покраснеют во вьюпорте — и удалите. Выбрать всё: <kbd>Ctrl</kbd>+<kbd>A</kbd>.

### 7 · Клик правой кнопкой по острову — работа с этим островом

Модели из островов редко хотят одного и того же везде. Клик правой кнопкой открывает меню вокруг того, что под курсором, — и заранее говорит, каких островов коснётся.

| | |
|---|---|
| **Двигать…** | Ручка-перемещение на выборе. Оттащите остров от тела, разложите детали по столу, отпустите — применится. Esc — отмена. |
| **Упростить** | Оставить 50%, 25% или 10% — *только этим островам*. Громоздкое основание утоньшается, а фигурка сверху сохраняет каждый треугольник. |
| **Слить в одно тело** | Булево объединение, а не склейка: две перекрывающиеся половины становятся одним герметичным телом, которое слайсер зальёт. Не касающиеся острова так и скажут, а не притворятся слитыми. |
| **Оставить только эти** / **Удалить** | Изолировать нужное или выбросить лишнее. |

Клик правой по невыбранному острову сначала выбирает его. Shift+правая добавляет к выбору, как shift+клик, — а **Alt+drag тянет рамку** по вьюпорту и забирает всё внутри разом: именно это делает рабочей модель, распавшуюся на триста островов. Всё синхронно с панелью островов, каждое действие — номерное состояние с отменой.

### 8 · Кольца под литьё

ИИ-сервис выдаст кольцо за минуту. Носить его почти наверняка нельзя: посадка — овал, размер — какой генератор захотел, внутренняя кромка — квадратная, а шинка тонка там, где металл не зальётся. Обычный ремонт закрывает дыры и отдаёт герметичный, идеально неносибельный овал.

Откройте карточку **«Ювелирка»** — по умолчанию свёрнута, аудитория маленькая, — задайте размер пальца и минимальную стенку, нажмите **«Починить это кольцо»**:

```
БЫЛО   посадка 16,40–17,90 мм · ISO 51,5 / US 5,87 · 33% острых граней
       «Посадка некруглая на 1,50 мм. Пальцу нужен круг, а это овал.»

СТАЛО  2,4 с · герметично · 0% острых граней
       Размер при печати   ISO 56   · US 7,64
       Размер после литья  ISO 54,4 · US 7
```

Meshwright измеряет; **Blender** делает геометрию, недоступную треугольной сетке. Комфортная посадка режется под ваш размер — уже в середине, шире к краям, — одним движением чиня круг, размер и острую внутреннюю кромку. Фаска по углу снимает жёсткие углы и не трогает плоские места и гравировку: на кольце с канавками 0,3 мм каждая осталась глубиной ровно 0,300 мм. Воксельное скругление, очевидная альтернатива, такую мелочь замыливает.

Укажите `blender.exe` один раз кнопкой **«Найти Blender…»** — запомнится. Без Blender замеры работают, а починка объяснит, чего ей не хватает.

Уверенно врать он отказывается: расточка только убирает металл, так что посадка, изначально шире просимой, круглой не станет — панель так и скажет, назвав наименьший размер, при котором круг выходит; сплошную модель завернёт, а не выдумает ей размер пальца; а при заданной усадке размер при печати и после литья показываются отдельно, потому что на экране — восковка, а не кольцо.

Каждый предел, по которому он судит, опубликован с источниками в [docs/PRD-RINGS.md](docs/PRD-RINGS.md).

### 9 · Открывайте только нужные части

В файле часто больше, чем модель. Проект Blender под рендер притаскивает пол студии, отражатели и контроллеры рига; сцена в GLB — что ещё в ней было. Meshwright раньше сваривал всё в одну сетку, и разделить обратно было уже нельзя: в одном реальном проекте «модель» намерилась 200 × 200 единиц, потому что к роботу 5,4 × 2 × 10 приплавилась одногранная земля.

Теперь такой файл сначала перечисляет содержимое — с именами, треугольниками и размерами, по вашим коллекциям:

```
01 • Торс и центральные механизмы         15/15
02 • Голова, глаза, шарнирная челюсть     15/15
03 • Левые конечности — отдельно          36/36
04 • Правые конечности — зеркально        36/36
06 • Контроллеры (скрыты при рендере)      0/3   ← сняты автоматически
90 • Студия и камеры                       3/3   ← один клик — и пола нет
```

Сваривается только отмеченное; остальное в файле не тронуто. Файл с одним объектом открывается как раньше, без вопросов.

Перечень намеренно дешёвый — поэтому спрашивать не накладно: проект Blender читается за секунды, где экспорт — минуты, а glTF читается из собственного JSON-заголовка: файл на 426 МБ перечисляется, не трогая эти 426 МБ.

**Ничего не угадывается.** Объекты, которые сам файл помечает как не-для-рендера, изначально сняты — контроллеры рига так про себя и говорят. Остальное изначально отмечено: проект-виновник называет свою землю 200×200 *«Studio ground • excluded from model validation»* и не несёт ни одного флага об этом, а настоящая плитка пола в печатной диораме выглядит ровно так же для любого хитрого правила. Вместо правил работает группировка.

### 10 · Проверка печати — напечатается ли вообще?

Выберите принтер, на котором печатать, и Meshwright измерит, осилит ли машина мелочь физически. Вшито **216 машин** — смола и филамент: Elegoo, Anycubic, Phrozen, Creality, Bambu Lab, Prusa и ещё два десятка марок, — а если стоит слайсер, предлагаются и его машины с пометкой *на этом ПК*. Сопло, пиксель и слой перебиваются руками: сопло — расходник, а что стоит — знаете вы.

Предел разный для двух типов машин. Смола упирается в экран: у Elegoo Mars 4 Ultra 153,4 мм на 8520 пикселей — пиксель 18 мкм, а мельче всего запекается примерно два. Филамент упирается в сопло: уже себя дорожку не положит. **Одна модель на одном идеальна, на другом безнадёжна** — теперь говорится, на каком.

Слишком тонкое перечисляется, считается и кликается — подсвечивается на модели, как любая диагностика. Где мелочь потеряется — говорится размер, при котором уцелеет всё, в миллиметрах и в кратах (*«в размере 8×, высотой около 7,9 мм, уцелеет всё»*) — важно, потому что сгенерированные модели обычно приходят ростом около миллиметра.

**Ничего не утверждается, пока не сошлись два независимых замера.** Каждый слой режется и рисуется в родном разрешении принтера, морфологическое открытие убирает ровно то, что машина не положит, — этому замеру не нужны ни нормали, ни герметичность, так что решает он. Отдельно в поверхность у каждой грани пускается луч замера стенки — за Embree от Intel это 336 780 точных замеров за 0,4 с, а на сфере известной толщины 10,000 мм он возвращает 10,000. Но он прав, только пока поверхность смотрит куда надо: на одной реальной модели на 694 000 граней с рваным обходом он намерил ровную стенку 0,24 мм сквозь сплошную фигуру. Поэтому решать в одиночку ему не дают: на сетке с сомнительным обходом или герметичностью его находки скрываются, панель говорит почему, а где замеры расходятся — само расхождение и есть находка. Проверка, которая молча гадает, хуже никакой: она отправляет на шестичасовую печать.

Таблица вшита — работает и без слайсера; где слайсер *есть*, его машины подтягиваются из его же конфига — на них человек и печатает. Каждая цифра в таблице — из опубликованных характеристик, любую можно перебить под машину, которой в списке нет.

### 11 · Откройте файл — и увидьте, что это

Миниатюры 3D Windows рисует через Microsoft 3D Viewer, которого в Windows 11 больше нет, — стандартный диалог показывает ряд одинаковых пустых иконок и имя файла на угадывание. Поэтому **«Открыть модель»** открывает собственный браузер Meshwright: подсветите файл — нарисует модель и доложит формат, размер, число треугольников, габариты, есть ли текстуры и сколько примерно открывать. Картинки подтягиваются рядом со строками — папка читается взглядом, а открытое раньше лежит в шаге под **«Недавние»**.

Картинка не требует загрузки. Каждый файл семплируется — читается напрямую не больше пары сотен тысяч треугольников — и семпл брызгается в мелкую картинку глубины-и-нормалей со светом: цена следует за семплом, а не за моделью. STL на 249 МБ и пять миллионов граней рисуется около 0,7 с, GLB на 67 МБ — около 0,2 с против 7,7 с настоящего открытия этого GLB. Картинки лежат в `%LOCALAPPDATA%\Meshwright\previews` — второй раз папка мгновенна; где у файла своя миниатюра (как у 3MF от слайсера) — берётся она.

Числа — собственные у файла или помеченные: габариты STL — по всем его треугольникам, glTF — по заявленному, а где файл слишком велик для точного замера — размер с `≈`. Форматы, которые дёшево не семплируются — FBX тяжелее 64 МБ, COLLADA, 3DS, очень большой 3MF, — докладывают факты и говорят, что картинка будет после открытия.

Рассчитано на живой диск. Битый файл объясняется, а не рисуется; файл, заявляющий больше данных, чем содержит, отклоняется, а не читается: ничего не memory-mapped — выход за конец映射ённого файла убивает процесс, а не исключение. Папка, которую Windows не открывает, так и говорит и «удалённой» не притворяется; файл, висящий в облаке OneDrive, оставляется в покое, а не скачивается молча; диски читаются из списка, который держит Windows, — отвалившийся сетевой диск диалог не вешает. Фоновые картинки всегда уступают тому, чего вы ждёте, — навигация мгновенна.

Диалог Windows — в одном клике, drag-and-drop без изменений, <kbd>Ctrl</kbd>+<kbd>O</kbd> открывает новый браузер.

### 12 · Ничего не теряется

Каждое изменение — **номерное состояние**.

- <kbd>Ctrl</kbd>+<kbd>Z</kbd> / <kbd>Ctrl</kbd>+<kbd>Y</kbd> ходят между состояниями — больше ничто назад не ходит.
- Изменение, которое **добавит критичных проблем** или **выбросит почти всю геометрию**, отклоняется, прошлое состояние остаётся, предлагается «применить всё равно».
- Каждое принятое состояние фоном пишется в снимок. Упало — при следующем старте предложит **восстановить**.
- **Вернуться к исходнику** — явно, с подтверждением, и само отменяется.
- **Новое** (<kbd>Ctrl</kbd>+<kbd>N</kbd>) и <kbd>Del</kbd> закрывают модель и чистят рабочее место, с подтверждением.

### 15 · Экспорт

STL, OBJ, PLY, OFF, GLB, glTF или 3MF с масштабом исходных единиц (мм / см / дюймы) и посадкой на стол, плюс **JSON-отчёт** о диагностике и каждой применённой операции — для приёмки заказчиком или аудита печатной фермы.

OBJ, GLB и glTF уносят UV-координаты и PBR-карты с моделью. В STL, PLY, OFF и 3MF их положить некуда — пишется только геометрия, слайсеру того и надо.

Meshwright проверяет сетку прямо при записи и говорит на экране, когда файл **не замкнутое тело**: открытая поверхность даёт у слайсера одностеночную скорлупу без заполнения, какие настройки ни крути. Вывернутые модели по дороге в файл разворачиваются наружу.

## Автоматизация — MCP-сервер и Python API

Десктоп — тонкая оболочка над одним движком. Тот же движок доступен ассистентам, редакторам и скриптам.

```jsonc
// claude_desktop_config.json
{ "mcpServers": {
    "meshwright": { "command": "python", "args": ["D:/path/to/Meshwright/mcp_server.py"] }
} }
```

14 инструментов — `load_model, analyze, repair, fix_slivers, simplify, retopologize, remove_shells, rotate, undo, redo, revert, states, export_stl, export_report` — плюс ресурс `meshwright://report`.

```python
from engine.service import MeshService

svc = MeshService()
svc.load("dragon.fbx")                         # UV и PBR-карты приедут вместе
svc.repair()                                   # измерено, проверено, отменяется
svc.retopo(20000, method="quadriflow")         # умная ретопология, UV едут следом
svc.export_model("dragon_low.glb", "glb")      # геометрия, UV и материал
svc.export_stl("dragon_print_ready.stl")
```

Каждый ввод проверяется, каждый вызов застрахован и отменяется. См. **[docs/MCP.md](docs/MCP.md)** и **[docs/API.md](docs/API.md)**.

## Форматы

Проекты Blender требуют установленного Blender. Meshwright находит Blender в PATH или в обычных местах Windows/macOS; `MESHWRIGHT_BLENDER` указывает на свой. Активная сцена импортируется с модификаторами, трансформациями и glTF-совместимыми материалами через временный GLB. Исходники не трогаются. Что Blender сам не стал бы рендерить — контроллеры рига, выключенное в аутлайнере, — остаётся за бортом, а остаток перечисляется, чтобы открыть только нужное. Координаты Blender сохраняют численный масштаб; при экспорте выберите подходящие исходные единицы. В браузере файлов проекты Blender перечисляются без миниатюры.

**Вход** — BLEND · OBJ · FBX · GLB · GLTF · STL · PLY · 3MF · DAE · OFF · 3DS
**Выход** — STL (бинарный) · OBJ · PLY · OFF · GLB · glTF · 3MF · JSON-отчёт · пак текстур PBR

Текстуры приходят вшитыми в файл или картинками рядом и уходят обратно в OBJ, GLB и glTF либо папкой PNG с UV-подложкой для Photoshop.

Модели приходят **как надо вверх**. Meshwright работает в Z-вверх, как каждый слайсер и стол, а glTF и GLB по своей спеке всегда Y-вверх, FBX пишет свой ответ в файл, — поэтому те разворачиваются вверх на входе и обратно на выходе: GLB отсюда — Y-вверх, как требует формат, и повторное открытие возвращает ту же модель. Форматы, про ориентацию не пишущие (OBJ, PLY, OFF, 3DS), остаются как были сохранены: угадывание по форме одни поставит, другие положит, и не различить. 

Каждый экспорт — с масштабом единиц, уложен на стол, проверен на тело и назван `<original>-GS-<timestamp>-fixed.<ext>` — открытое не перезапишет никогда.

## Неполадки

### «Python was not found; run without arguments to install from the Microsoft Store»

В Windows из коробки лежит **заглушка** `python.exe`, которая только это и печатает. Она в `PATH` сразу, так что кажется, будто Python стоит, хотя его нет. Лечится любым способом:

- Поставьте Python с [python.org](https://www.python.org/downloads/windows/) и в первом экране установщика включите **«Add python.exe to PATH»**. Затем откройте **новое** окно и снова `install.bat` — старое помнит прежний `PATH`.
- Или выключите заглушку: **Параметры → Приложения → Дополнительные параметры → Псевдонимы выполнения**, выключить **python.exe** и **python3.exe**.
- Python уже стоит в необычном месте? Укажите напрямую:
  `install.bat -Python "C:\Path\to\python.exe"`

`install.bat -Check` перечисляет каждый интерпретатор, который видит машина, — быстрее всего понять, что там реально есть.

### «[ERROR] Could not create the virtual environment»

Раньше это печаталось сразу после сообщения выше: заглушку принимали за Python. Нынешний установщик проверяет каждый интерпретатор запуском, так что теперь это значит что-то другое — что именно, говорится:

- **В папку нельзя писать.** Уберите Meshwright из `Program Files`, из read-only шары, лучше из OneDrive — куда-то вроде `C:\Meshwright`.
- **Запуск изнутри ZIP.** Сначала распакуйте: правый клик по ZIP → *Извлечь всё…*. Двойной клик по `install.bat` внутри ZIP распаковывает копию во временную папку, которую Windows потом удаляет.
- **Мешается недособранный `.venv`.** Запустите `install.bat -Recreate`.

### Установка кончилась «Engines skipped: …»

Это не ошибка. Эти движки — компилируемые расширения, а под Python, вышедший пару недель назад, готовых сборок обычно нет ещё месяцы. Meshwright работает и сообщает, какие методы ремонта/ретопологии недоступны; поставьте **Python 3.12** и `install.bat -Recreate` — будет полный комплект.

### Meshwright открылся, а модели нет

С Meshwright моделей не поставляется — нечего качать, некуда указывать. Он работает с вашими файлами: **«Открыть модель»**, <kbd>Ctrl</kbd>+<kbd>O</kbd> или перетащите файл на окно. Для пробы нажмите **«Загрузить демо-модель»** в пустом вьюпорте: в памяти соберётся мелкий нарочно битый объект — на нём видно и диагностику, и ремонт.

**«Открыть модель»** открывает собственный браузер, а не Windows: картинок 3D-файлов у Windows нет — миниатюры она рисует через Microsoft 3D Viewer, которого в Windows 11 нет. Подсветите файл — Meshwright нарисует модель и доложит формат, размер, треугольники, габариты, текстуры и сколько примерно открывать, — не открывая, за долю времени открытия. Открытое раньше — под **«Недавние»**, а **«Диалог Windows…»** даст обычное окно, если привычнее.

Чёрное окно терминала рядом — журнал работы. Не закрывайте: закроете его — закроется Meshwright.

### Экспортный STL режется тонкой скорлупой — один слой, без заполнения

Слайсер прав: файл — **поверхность**, а не тело. У закрытого объёма слайсер заливает внутренность; у открытой поверхности внутренности нет — выходит одностеночная скорлупа при любом заполнении.

Meshwright теперь говорит это вслух при записи («Сохранено, но это не печатное тело»), а панель диагностики флагает заранее — ищите **открытые дыры** и **граничные рёбра**, оценка готовности будет низкой. Лечение: **«Починить»** и экспорт заново; панель должна сказать *герметично* — только тогда слайсер сочтёт модель телом.

Два смежных случая, про которые тоже предупреждает экспорт:

- **«Модель полая, стенки в среднем 0,4 мм».** Модель правда скорлупа — часто скан или поверхность из CAD с нулевой толщиной. Толщину — в программе, откуда пришла, либо режим вазы/спирали в слайсере осознанно.
- **Вывернутые модели.** Meshwright разворачивает обход наружу по дороге в файл: сетка, которую слайсер читал полостью, выходит телом.

### Что-то ещё

Каждая установка пишет `install-log.txt` рядом с `install.bat`, а `.venv\Scripts\python scripts\check_install.py` печатает, какие движки есть в вашей копии. Эти два вывода и прикладывайте к багрепорту.

## Разработка

```bash
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements-dev.txt
npm install       # докачивает Three.js в ui/vendor и ставит eslint

npm test          # pytest, 347 тестов
npm run lint      # eslint + ruff
npm run mcp       # старт MCP-сервера
```

Версии в `requirements.txt` намеренно ограничены сверху (`numpy>=1.26,<2.6` и т.д.): установка никогда не утащит общее окружение на несовместимое. Всему, чему нужен компилятор, место в `requirements-optional.txt`, никогда в `requirements.txt`.

### Сборка установщика Windows

```powershell
.venv\Scripts\python -m pip install -r requirements-build.txt
powershell -ExecutionPolicy Bypass -File packaging\build.ps1
```

Заморозит Meshwright в программу, которой Python не нужен, докажет работоспособность собственным самопрогоном из 18 шагов и упакует в `Meshwright-Setup-<version>.exe`. Два издания (с GPL-движками и без) и проверка установщика без риска для данных — в [packaging/README.md](packaging/README.md).

## RU-форк — что здесь изменено

Относительно оригинала [GeekatplayStudio/Meshwright](https://github.com/GeekatplayStudio/Meshwright):

- **Интерфейс EN/РУ** (`ui/js/i18n.js`, кнопка в верхней панели, выбор запоминается). Английский остался языком по умолчанию и языком всех бэкенд-сообщений.
- **`install.bat`** — поиск PowerShell запуском, а не через `where` (он отвергал полные пути и врал, что PowerShell нет).
- **`scripts/Find-Python.ps1`** — отсеиваются встроенные интерпретаторы с POSIX-раскладкой venv (например, Python внутри Inkscape).
- **Мобильная папка проекта**: `install.ps1` метит, где собран `.venv`; `start.ps1`/`start.bat` после переезда пересоздают окружение сами; `run-mcp.bat` предупреждает о переезде.
- **Документация и этот файл** — на русском; оригиналы лежат рядом как `*.en.md`.
